# 真实故障复盘：定时任务叠加导致 CPU 持续 100%

> 来源：椰云网络《服务器 CPU 突然飙到 100% 怎么办？一次真实排查过程记录》
> 链接：https://www.yeziidc.com/newscontent/318.html

## 现象
- 网站访问明显变慢，但无报错
- 后台仍能打开，但响应延迟明显
- SSH 登录有卡顿，服务器负载明显升高
- CPU 接近 100%，且是持续占用而非瞬间波动

## 排查过程
1. `top` 查看：CPU 持续接近 100%，按 CPU 排序后发现一个 PHP 相关进程长期占用 70%+，另有辅助脚本持续运行。
2. `ps -aux | grep php` 追查进程来源，发现并非正常访问产生，而是定时任务触发的脚本。
3. `crontab -l` 检查定时任务，发现有一个日志处理任务每分钟执行一次。

## 根因
- 日志文件体积过大
- 定时任务每次都要重新扫描处理
- 单次执行时间超过间隔时间（1 分钟），导致任务叠加
- 上一次任务还没跑完，下一次又启动，形成无限叠加，CPU 被持续占用

## 解决方案
1. 优化日志处理逻辑，避免每次全量扫描
2. 调整定时任务执行间隔，确保单次执行时间小于间隔时间
3. 为定时任务加锁，避免任务重叠执行

## 复盘启示
- CPU 飙高是「症状」而非「根因」，要追到「谁在占资源」再追「为什么占」
- 定时任务叠加是 CPU 持续飙高的经典原因，排查时要检查 crontab 里执行时间与间隔的匹配关系
- 持续占用（非瞬间峰值）通常意味着「卡住循环执行」，方向与瞬时流量突增不同
